# Hamster Runtime

테트로미노 튜브로 길을 깔고, 그 위에 센서·기어·모터·스위치·마개 부품을 얹어 기계를 만드는 웹 퍼즐.
**2차: 레벨 19개 + 가격 + 레벨 에디터** (키보드 전용, 데스크톱). 사이트: https://kjh-code.github.io/Hamster-Runtime/

## 실행
```bash
npm install
npm run dev        # 개발 서버
npm test           # 단위 테스트
npm run build      # 타입 검사 + 빌드
```
`main` 에 push 하면 GitHub Actions 가 테스트 → 빌드 → Pages 배포.

## 레벨
- 첫 화면 = 레벨 카드. 방향키로 고르고 Enter. 앞 레벨을 클리어하면 다음 레벨이 열린다 (맨 아래 = 샌드박스)
- **클리어** = 대기열을 끝까지 돌린 뒤 모든 통의 빨강·파랑 마릿수가 조건과 같고, 총 가격 ≤ 예산
- **처음 하는 사람**: 1번에 처음 들어가면 다른 작은 판에서 자동 플레이 데모를 먼저 보여 준다 (아무 키 = 시작). 1번(미노 하나, 가격 없음)은 판 위 말풍선이 투입구 → 목표 통 → 몇 번 키를 누를지(팔레트 칸 반짝임) → 옮기기·돌리기 → 떨어뜨리기 → 실행을 한 단계씩 안내한다 (해내면 다음, N 건너뛰기·다시 보기). 안내가 떠 있는 동안 자동 낙하는 멈춘다. 2번은 가격과 두 미노 잇기, 3·4번은 새 조작, 6번(마개)은 말풍선 한 번. 7번(스위치)·8번(센서·모터·기어)은 갈림길을 다 지으면 부품을 하나씩 빛나는 칸에 놓도록 단계별로 안내한다. 나머지는 스스로. 목표 없는 통은 흐리게 보인다
- **떨어뜨려 쌓기가 기본**: 미노는 바닥이나 다른 미노 위에만 놓인다. 높은 길은 빈 미노로 받치고, ↓ 로 내린 뒤 옆으로 밀면 처마 밑에도 넣는다. 고정 미노(어둡고 못 박힌 것)는 제약용
- **레벨 19개**: 1 첫 미노 · 2 첫 길 · 3 받침대 · 4 끼워 넣기 · 5 두 계단 · 6 마개 · 7 선로 전환 · 8 첫 손님만 · 9 번갈아 · 10 고장 내기 · 11 색 나누기 · 12 직접 짓기 · 13 한 줄에 둘 · 14 합류 문 · 15 처마 밑 토글 · 16 양쪽 색 나누기 · 17 안쪽부터 · 18 그 자리에 멈춰 · 19 두 단 토글 (12~ 은 심화: 쌓기+부품 복합, 두 투입구 / 17~ 은 최고 난이도: 처마 밑 쌓기 순서, 잠금 활용, 큰 기계). 파일 이름은 `00-…` 부터라 화면 번호와 하나 차이 (기존 기록을 지키려고 id 는 그대로)
- 판 바로 아래에 지금 쓸 키 3~4개만 나온다. 전체 키는 **?** (또는 H)
- **부품 동작 미리보기**: 부품 모드에서 맞물린 기어 줄은 노란 선, 센서→모터는 하늘색 점선, 센서마다 번호, 스위치 옆에 "1→B" (센서 1 을 지나면 B 쪽으로 민다). 커서를 부품에 대면 그 센서가 돌리는 칸마다 ↻ / ↺
- **힌트 T**: 처음엔 글 힌트(어디를 봐야 하는지), 다시 누를 때마다 다음 미노 자리 하나 → 미노가 다 맞으면 부품 자리 하나. 내가 놓은 미노가 참조 풀이와 다르면 그 미노를 살린 채 이어지는 수를 잠깐 찾고, 없으면 참조 풀이 기준으로 보여 주며 막는 미노를 빨간 테두리로. 힌트(자리)를 보고 낸 최저 기록에는 💡 (레벨 카드·끝 화면·풀이 보기). 글 힌트는 `src/data/hints.ts` 에서 직접 고친다
- 미노 15종은 2번부터 모든 레벨에서 쓸 수 있다 (1번은 L 튜브 하나만). 부품은 배운 만큼 늘어난다 (1~5 없음 · 6 마개 · 7 +스위치 · 8~ 전부). 예산 = 참조 풀이 가격 × 2 — 최저 가격 기록이 골프 목표
- **그림**: 물들인 나무 블록 + 투명 햄스터 튜브. 노란 고리 = 이어진 이음매, 주황 고리·화살표 = 열린 끝, 빨간 뚜껑 = 마개, 주황 점선 원 = 스위치 없는 분기점. 목도리 색 = 빨강/파랑 햄스터
- 화면에는 대기열 · 통 조건 · 총 가격/예산만 나온다. 레벨별 최저 가격은 브라우저(localStorage)에 남는다
- 미노는 **중력으로 떨어뜨려 쌓는다** (자동 낙하 없음). 부품은 놓인 미노 칸 위에 1차 규칙대로
- 미리 박힌 고정 미노·부품(어두운 칸)은 0원, 지울 수 없다. 미노는 마지막에 떨어뜨린 것만 지울 수 있다

| 키 | 미노 | 부품 |
|---|---|---|
| 1~7 / S G M W P | 미노 꺼내기 (판 옆 팔레트에 그림·번호) | 센서 · 기어 · 모터(다시 누르면 ↻↺) · 스위치 · 마개 — 누르면 바로 칸 커서 |
| Q / E | 튜브 ↔ 빈 변형 | |
| ← → / ↓ | 옮기기 / 빨리 내리기 — 꾹 누르면 미끄러짐 (DAS 150ms · ARR 40ms) | 칸 커서 (↑ 포함, 꾹 가능) |
| X / Z | 회전 | 스위치 공통 갈래 |
| Space | 바로 떨어뜨려 고정 | 놓기 |
| A / B | | 스위치 시작 방향 |
| Delete | 마지막 미노 지우기 | 부품 지우기 |

- 미노는 꺼내면 **천천히 저절로 내려오고**(0.8초에 한 칸), 바닥에 닿아도 저절로 고정되지 않는다. **Space 로 고정**
- 공통: Ctrl+Z / Ctrl+Y · R 실행/리셋 · F 빨리가기(1×·2×·4×) · 클리어 후 Enter 다음 · C 풀이 링크 · ? 전체 키 · Esc 목록(부품 커서일 땐 미노로)
- 판은 창 높이에 맞춰 커진다

## 풀이 공유 (서버 없음)
- 레벨을 깨면 **C** = 내 풀이 링크 복사 (`…/Hamster-Runtime/#s=코드`). 레벨 카드에서도 깬 레벨은 C 로 최저 풀이 링크
- 링크를 열면 **풀이 보기**: 받는 쪽 엔진이 다시 돌려 ✓ 클리어·가격 / ✗ 이유를 보여준다 (코드를 믿지 않음). R 재생, Enter 직접 풀기. 안 깬 레벨이면 스포일러 경고 먼저
- 링크 미리보기(카톡 등): `index.html` 의 og 태그 + `public/og.png`
- 모든 레벨을 깨면 끝 화면(레벨별 최저 / 예산, 합계)
- 서버가 필요한 공용 순위표·닉네임·피드백(막힌 레벨·한 줄 의견·별점)은 나중에

## 레벨 에디터 (샌드박스에서)
1. 샌드박스에서 판을 만들고 Tab 으로 대기열을 짠다
2. **F** 로 레벨에 미리 박을 미노(미노 모드)·부품(부품 모드)을 고정 지정
3. **L** 레벨 설정 모드: ↑↓ 항목, ←→ 숫자(판 가로·세로, 통별 빨강·파랑), Space 사용 가능 미노·부품 켜고 끄기, Enter 글자(id·이름·핵심 메커니즘)
4. **P** 현재 배치를 참조 풀이로 저장 — 중력으로 쌓을 수 있는 순서를 찾고, 엔진으로 돌려 통 조건을 확인한 뒤, 예산 = 참조 가격 × 2 로 `<id>.json` 을 내려받는다
5. **T** 시험 플레이 (기록 없음, Esc 로 샌드박스)
6. 내려받은 JSON 을 `src/data/levels/` 에 넣으면 파일 이름 순서대로 목록에 들어간다 (`16-...json`)

## 가격
`src/data/prices.ts` 에서 고친다 (초안: 튜브 미노 2 · 빈 미노 1 · 마개 1 · 기어 1 · 센서 2 · 모터 3 · 스위치 3).
값을 바꾸면 레벨 예산과 참조 풀이 가격이 어긋날 수 있다 → `npm test` 의 `tests/levels.test.ts` 가 레벨별로 알려준다. 그 레벨 JSON 의 `budget` 을 테스트가 말한 값으로 고친다.

## 레벨 JSON
```jsonc
{
  "id": "04-sensor-motor", "name": "첫 손님만",
  "mechanic": "이 레벨의 핵심 메커니즘 한 줄 (풀이 방법은 적지 않는다)",
  "w": 8, "h": 9,                                   // 통 개수 = 가로 / 2 (올림)
  "queue": [{ "color": "red", "inject": "left" }],  // 고정 순서
  "bins": [{ "red": 1, "blue": 2 }],                // 통마다 하나, 개수만
  "allowed": { "minos": ["O-empty"], "parts": ["switch", "sensor", "motor", "gear"] },
  "budget": 13,
  "fixed":    { "minos": [{ "id": "J-tube", "r": 0, "x": 0, "y": 2 }], "parts": [] },
  "solution": { "minos": [...떨어뜨리는 순서], "parts": [{ "x": 3, "y": 6, "type": "switch", "common": "N", "start": "A" }] }
}
```
미노 좌표는 중력 모드 SRS 자세(`r` 회전, `x,y` 상자 좌상단). 모터는 `"dir": "cw" | "ccw"`.
스폰 자리(맨 위 가운데 두 줄)는 비워 둔다 — 막히면 미노를 꺼낼 수 없다 (테스트가 검사).

## 샌드박스 조작 (키보드만)
| 키 | 미노 모드 | 부품 모드 | 대기열 모드 (Tab) |
|---|---|---|---|
| 숫자 / 글자 | 1~7 모양 (I O T S Z L J) | S 센서 · G 기어 · M 모터(다시: ↻↺) · W 스위치 · P 마개 | 1 빨강 · 2 파랑 |
| Q / E | 변형(튜브/빈) 순환 | | |
| 방향키 | 미노 이동 | 칸 커서 이동 | ↑↓ 선택 · ←→ 투입구 |
| X / Z | 회전 시계/반시계 | 스위치 공통 갈래 돌리기 | |
| Space / Enter | 놓기 | 부품 놓기 | 선택 뒤에 추가 |
| A / B | | 스위치 시작 방향 | |
| Delete | 겹치는 미노 제거 | 부품 제거(없으면 미노) | 삭제 |

공통: 숫자 = 미노 · 글자 = 부품 (모드 전환 없음) · 방향키 꾹 = 미끄러짐 · Tab 대기열 · ? 전체 키 · N 안내 · Ctrl+Z / Ctrl+Y 되돌리기/다시 하기 · R 실행/리셋

## 규칙 요약
- 판 10×14, 바닥 통 5개(폭 2). 투입구는 맨 위 왼쪽/오른쪽 끝 열
- **미노 = 튜브 경로.** 칸마다 튜브 또는 빈칸. 회전만, 뒤집기 없음
- **자동 연결**: 경로 중간 칸은 미노 안에서만 이어진다. 경로 끝 칸은 상하좌우의 *다른 미노의 열린 끝*과 서로 이어진다. 이어질 끝이 없으면 직진 방향(경로 반대쪽)으로 열린 출구가 된다. 같은 미노의 두 끝은 이어지지 않는다
- **분기점**: 연결이 3·4갈래인 칸. 스위치가 없으면 햄스터가 멈춘다(주황 테두리)
- **부품** (한 칸에 하나, 미노 칸 위에만)
  - 센서: 아무 미노 칸. 햄스터가 들어가면 상하좌우 모터가 자기 방향으로 돈다
  - 기어: 아무 미노 칸(튜브 위 포함). 맞물려 반대 방향으로 돈다
  - 모터 ↻/↺: 빈칸만. 구동 안 되면 기어
  - 스위치: 분기점에 끼우는 **ㄱ자 관**. 공통 갈래(흰 점)와 그 직각 갈래 하나만 잇는다 (일자 없음). A = 흰 점에서 반시계 쪽, B = 시계 쪽. 기어가 시계로 돌면 관도 시계로 90° (A→B), 반시계면 B→A, 갈 수 없는 쪽으로 밀면 거부. 흰 점은 양옆 직각 갈래가 둘 다 있는 쪽만 (T자는 기둥). 공통 ↔ 열린 갈래만 양방향으로 통하고, 다른 갈래로 들어오면 막다른 길
  - 마개: 경로 끝 칸만. 그 끝은 닫힌다
- **기어**: 회전은 맞물린 연결 요소 전체에 전파. 거부가 나면 요소 전체 잠김(빨강). 모순되게 동시 구동해도 잠김. 홀수 고리는 영구 잠김(격자에서는 생기지 않음)
- **햄스터**: 튜브를 따라 스스로 굴러감(위로도). 출구로 나가면 수직 낙하, 바로 아래가 위로 열린 입구면 받아짐. 부품 없는 빈칸은 통과, 그 밖에 닿으면 튕김
- **대기열**: 색(빨강/파랑) + 투입구. R 로 순서대로 한 마리씩. 통이나 멈춤이면 다음 마리. 스위치·잠김은 다음 마리로 이어진다. 통마다 색별 마릿수, 멈춘 마릿수 집계. 무한 루프는 알리고 중단
- 스위치가 놓인 분기점의 갈래를 바꾸는 편집은 거부된다(스위치를 먼저 지운다)

## 미노 데이터 수정
`src/data/minos.ts` 의 `MINOS` 만 고치면 된다.
```ts
{ id: 'L-tube', name: 'L 튜브', piece: 'L', rows: ['1 ', '2 ', '34'] }  // 숫자 = 경로 순서
{ id: 'T-tube-a', name: 'T ㄱ', piece: 'T', rows: ['12e', ' 3 '] }       // e = 빈칸, ' ' = 미노 아님
```
- 같은 `piece` 글자끼리가 같은 숫자 키, Q/E 로 순환
- `npm test` 의 데이터 검사(`tests/mino.test.ts` 첫 묶음)가 4칸·테트로미노 모양·경로 연속을 확인한다
- 규칙 테스트는 `tests/fixtures/minos.ts` 고정 복사본을 써서 미노를 바꿔도 깨지지 않는다
