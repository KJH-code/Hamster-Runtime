# Hamster Runtime — 샌드박스 (MVP 0단계)

테트로미노에 새겨진 튜브·센서·모터·기어·스위치로 기계를 조립하고, 햄스터를 굴려 규칙대로 동작하는지 눈으로 확인하는 샌드박스. 레벨·가격·로그라이크·떨어뜨려 쌓기는 아직 없다.

## 실행
```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 단위 테스트 (기어·햄스터 시뮬레이션)
npm run build      # 타입 검사 + 빌드
```

## 배포 (GitHub Pages)
`main` 에 push 하면 `.github/workflows/deploy.yml` 이 테스트 → 빌드 → Pages 배포를 한다. 레포 Settings → Pages → Source 를 **GitHub Actions** 로 한 번 설정해야 한다. `vite.config.ts` 의 `base: './'` 라 `https://<user>.github.io/<repo>/` 하위 경로에서도 동작한다.

## 조작
- 좌클릭 배치 / 우클릭 삭제 / **R** 회전(시계 90°, 거울 없음) / **Space** 실행·일시정지
- 도구: 배치, 삭제, 스위치 A/B(스위치 칸을 클릭해 시작 상태 변경). 초기화 = 판 비우기
- 투입구: 판 맨 위 줄의 왼쪽 끝 열 / 오른쪽 끝 열에서 수직 낙하 시작
- 실행: ▶ 실행, ⏭ 한 칸, ⟲ 리셋(스위치 시작 상태로 복귀), 속도 슬라이더
- **다음 햄스터 ↻**: 스위치·잠김 상태를 그대로 두고 새 햄스터를 투입. 토글이 지날 때마다 번갈아 바뀌는지 확인하는 용도

## 규칙 요약
- 판 10×14, 맨 아래 통 5개(폭 2칸). 햄스터는 한 번에 한 마리
- 튜브 칸은 열린 변(위/아래/왼/오)이 데이터로 정해져 있고, 이웃한 두 칸은 맞닿은 변이 **양쪽 다** 열려 있을 때만 이어진다
- 튜브 안에서는 스스로 굴러 이동(수평·위·아래). 튜브 밖(빈 칸)으로 나가면 수직 낙하, 바로 아래가 위로 열린 튜브 칸이면 받아서 계속 간다
- 낙하 중 빈 판 칸·미노의 빈칸은 통과. 입구가 위로 안 열린 튜브 칸이나 비튜브 부품 칸에 닿으면 튕김 → 실패
- 막다른 길이면 멈춤 = 실패. 판 맨 아래를 넘으면 그 자리 통에 기록. 판 좌우·위로 나가면 실패
- (위치, 진행 방향, 모든 스위치 상태, 잠금)이 반복되면 무한 루프로 알리고 멈춘다
- 센서는 압력판: 햄스터가 그 칸에 들어가면 상하좌우 인접 모터가 자기 방향으로 돈다. 구동 안 된 모터는 기어
- 인접(상하좌우)한 기어 칸끼리 맞물려 반대 방향으로 돌고, 회전은 연결 요소 전체에 전파된다
- 스위치: 시계 = A→B, 반시계 = B→A. 이미 그 상태에서 같은 방향이면 회전 거부 → 그 연결 요소 전체 잠김(빨간 표시, 리셋까지 유지)
- 같은 연결 요소를 모순되게 동시에 구동하면 잠김. 하나만이거나 서로 일치하면 허용
- 홀수 길이 기어 고리는 영구 잠김. 단, 격자 4방향 인접에서는 홀수 고리가 수학적으로 생길 수 없어 판에서는 발생하지 않는다(코드와 테스트는 일반 그래프로 구현)

## 미노 데이터 수정
`src/data/minos.ts` 의 `MINOS` 배열만 고치면 된다. 팔레트·회전·시뮬레이션이 전부 이 데이터를 읽는다. 칸 토큰은 파일 위쪽 주석 참고.
```ts
{ id: 'I-sensor', name: 'I-센서', rows: [['tube:NS'], ['sensor:NS'], ['tube:NS'], ['tube:NS']] }
```
- `tube:NS` 열린 변(N 위·E 오른쪽·S 아래·W 왼쪽). 튜브·센서 칸은 정확히 2개
- `switch:S,W,E` = 공통 변, 상태 A 갈래, 상태 B 갈래. 닫힌 갈래로 들어오면 막다른 길
- `motor:cw` / `motor:ccw`, `gear`, `empty`(미노 칸이지만 요소 없음), `''`(미노 아님)
- 테트로미노 4칸·연결 여부와 튜브 칸의 열린 변 개수는 `tests/mino.test.ts` 가 검사한다

## 구조
```
src/data/minos.ts   미노 목록 (데이터)
src/core/           순수 로직 (DOM 없음): board, mino(회전), gears(기어), hamster(상태머신)
src/ui/             Canvas 렌더링·입력·컨트롤
tests/              단위 테스트
```

## 구현 중 둔 가정 (재혁 확인 필요)
- 투입구는 맨 위 줄 좌우 끝 열. S/Z 미노는 모터 1칸 + 기어 3칸(모터 위치는 데이터에서 변경)
- 센서는 햄스터가 그 칸에 들어갈 때마다 인접 모터를 구동
- 같은 연결 요소의 모터 두 개가 "같은 방향"인지는 맞물림 패리티로 판단한다(이웃한 모터가 시계/반시계면 일치, 둘 다 시계면 모순 → 잠김)
- 스위치 거부는 연결 요소 단위: 요소 안 스위치 하나라도 거부되면 어느 스위치도 안 바뀌고 요소 전체가 잠김
- 스위치 칸의 닫힌 갈래로 들어오면 그 스위치 칸에서 멈춤(막다른 길)
